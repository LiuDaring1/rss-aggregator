# ZCode → Antigravity｜整套项目打包与交接任务书 v1.0

## 0. 这次任务是什么

用户要把当前项目交给 Google Antigravity 中的 Agent 继续开发和制作周刊。目标是同一台电脑上的独立项目副本，不是换服务器，不是重写系统，也不是继续让 ZCode 修改下一版刊例。

本轮请实际完成：盘点 → 创建桌面交接目录 → 复制代码与必要数据 → 整理可执行的交接说明 → 在副本中验证 → 告知用户准确的打开路径。

新 Agent 接手后，应当既能继续使用信息聚合站和资料库，也能重新生成现有刊例，并准确理解老师的编辑要求。不能只交 GitHub 链接、sample.md、PDF 或一份计划。

本任务书和随附 `02_当前产品与编辑要求.md` 共同构成本次交接要求。最新教师澄清优先于旧任务书：**观点页充分展开多个不同观点；最终范本才选择一条主线，用两个主体段论证。两者绝不能混同。**

## 1. 项目背景与当前停止点

项目最初是评论 RSS 聚合站，后来增加暖文雷达、本地全文资料库和周刊生产。最终服务对象是高中播音艺考生：平日设备受限，以纸面阅读、复述、熟读背诵和积累为主。教师每周交付一份资料，不是在建设复杂远程课程。

当前重点是刊例内容质量，尤其评论的立意、发散思考、论证结构和口语表达。不是优先扩大全网采集。

本次已知审阅基线是 `weekly/sample-01-rev5/`，此前 `sample-01/` 至 `sample-01-rev4/` 为历史版本。请核实本机是否还有未推送、未提交的新内容：若有，保存并明确标记，不默默覆盖 rev.5，也不把后缀“5”等同于教师已经定稿。

老师对当前评论仍不满意。尤其需要明确：
- 观点页被压成两个观点，是执行误读，不是老师的新要求。
- “两段主体”只限定最终示范的组织，不限定思考页的角度数量。
- 现稿、教师备注里的“检查通过”以及助手给出的试改，都不能自动当成教师认可的成品标准。
- 更换 Agent 和模型是一次新的尝试，不宣称新模型一定更好。

## 2. 交接的保护边界

1. 默认复制，不搬走、不删除、不覆盖原工作区。新目录已存在时自动追加时间戳，保留原内容。
2. 不修改原站生产数据、不重置游标、不清空分析、不回填几千条案例、不批量重新调用 AI。
3. 不自动停止旧站，也不启动第二份指向旧数据的采集或分析任务。
4. 不运行可能无差别停止旧服务的脚本，不使用全局 `pkill` 等方式处理端口冲突。验证时使用空闲端口与副本数据，只停止本次创建且已记录的进程。
5. 本次不推送 GitHub、不 force push、不切断旧环境。用户看过接手结果后，再决定后续开发分支和生产切换。
6. 只盘点当前项目、已知关联目录及用户提供的参考包。不全盘搜其他项目，不复制其他应用的整个用户目录。
7. 用户同机私密交接所需的数据可以保留；公开仓库能发布什么是另一回事，不能把两种打包口径混为一谈。

## 3. 先核对实际项目，不照抄旧 README

请检查当前实际工作目录、独立 Git 仓库或 worktree 关系、分支与提交、未提交修改、未跟踪的重要文件，并记录快照时间。

已知路径只是核对入口，不能替代实际检查：
- `aggr-site/`：聚合站、暖文雷达、采集/合并/分析与本地阅读。
- `aggr-site/data/wenwen/`：本地正文和索引等实际数据。
- `data/`：给外部审阅的数据导出，不能默认等于完整资料库。
- `upstream-custom/`：对 RSSHub、we-mp-rss 的自定义路由、补丁和适配。
- 本机可能另有 `rsshub/`、`we-mp-rss/` 等完整上游工程和运行数据。
- `weekly/`：各版刊例及其内容数据、排版源码、生成脚本、图示和成品。
- 启停脚本、依赖清单、锁文件、测试、配置模板、代理与浏览器设置。

**不要直接运行旧 `package.sh` 就宣布交接完成。**本次检查到仓库的该脚本面向源码分享：排除了 data、密钥、Git 等内容，而且待打包列表没有 weekly。它不适合直接承担本次整套工作交接。请核对当前脚本后另做本地交接，不改变旧脚本原有的公开分享用途。

请找出周刊真正的编辑入口。例如当前 rev.5 的 `build5.py` 从 `content5.py` 读取内容，`render.sh` 调用 Chrome 打印 HTML。要交代修改哪个源文件、如何生成 Markdown/HTML/PDF和分册，不能只说“编辑 sample.md”，导致下次生成被覆盖。

同时分清：
- 哪些文字由 ZCode 会话中的模型直接撰写；
- 哪些功能由站内配置的 API 模型调用完成；
- 哪些代码只是把已有文字排版。

**更换 Antigravity 对话中的模型，不代表 `ai.json` 或其他代码中的模型配置自动改变。**请记录实际配置作用，但本轮不擅自替换所有模型、启动全量重算或新增模型平台。

## 4. 桌面目录：打开后能直接接手

建议目录名为 `口语素材周刊_Antigravity`，在当前用户的实际桌面创建。不要硬编码用户名。以下为建议结构，少量调整可以，但入口必须清楚：

```
口语素材周刊_Antigravity/
├── README_先读我.md              # 唯一开始入口、真实路径、阅读顺序、接手指令
├── CURRENT_REQUIREMENTS.md       # 从本参考包的最新编辑要求复制，不让历史规则盖回去
├── HANDOVER.md                   # ZCode根据实际工作区生成：架构、入口、命令、数据位置、缺口
├── CHECKS_AND_MANIFEST.md        # 实际复制清单、数据快照说明、验证结果
├── project/                     # 可独立编辑的项目副本，保留工程结构和必要Git信息
├── references/                  # 教学原件、历史规范、必要的匿名示范与反馈
└── _private/                    # 仅本机的必要配置或敏感运行资料，不提交Git
```

目录应是一个真正独立的接手工作区，不能只建指向旧工作区的软链接。若原工程是 Git worktree，要处理 `.git` 指针和 common-dir，不能复制一个仍依赖旧路径的空壳。

优先保留项目 Git 历史与原始 remote 信息。可以独立本地 clone 后叠加工作区修改，也可以采用其他可靠方法；未提交修改和重要未跟踪文件不得丢失。不要使用强制清理或覆盖来获得“干净工作区”。实际有敏感文件进入 Git 历史时，先记录风险，不在本轮擅自重写历史。

根交接目录不要再整体初始化并推送到公开仓库。`references/` 和 `_private/` 不属于公开提交范围；在 `project/` 内也核实私密文件未被跟踪，不能只添加 ignore 就当作安全完成。

## 5. 必须带走的四类内容

### A. 代码与生产能力

复制聚合站、暖文雷达、资料库界面、周刊制作源码、样式、生成脚本、图示数据、必要图片与配置模板，以及测试和锁文件。

保留全部现有刊例版本，作为修改记录和回退依据；标记哪些仅供历史查看，不让新 Agent 把旧稿自动选为最新稿。

对第三方上游，记录实际仓库地址、已用提交或版本、应用的自定义补丁及依赖。可以复制现有源码或提供经验证的固定版本恢复办法；不只写“安装最新版”。不要遗漏本机未进入 `upstream-custom/` 的实际修改。

一般不复制 `node_modules`、虚拟环境、大型浏览器缓存、临时日志和下载垃圾。保留可重建这些依赖的清单。记录实际 Node、包管理器、Python、浏览器和字体名称及发现路径；不从系统目录提取或分发字体文件。

### B. 数据与原始来源

保存已有资料库的完整可用副本：原始 HTML/正文、Markdown、本地文章及事件索引、来源表、合并关系、分析结果、用户保留/忽略反馈、增量游标、已用文章和来源链接等。

不是只复制 `data/report.md` 或 `candidates.json`，更不只是复制当前8条材料。已经积累的事实与评论原文是后续选题和写作依据。

活动数据使用一致性快照方式保存，记录采集截止时间。实际使用数据库时，用相应可靠备份机制；是多个 JSON/Markdown 文件时，保证索引与正文属于同一快照，必要时只短暂停写并立即恢复。不能裸拷贝一份正在变化的数据后宣称一致。

副本可在原有相对目录下恢复并设置忽略，或采用单独数据目录；选择对现有代码改动最少的方案。无论放在哪里，新环境都不得写回旧站数据。检查软链接和绝对路径，列出仍依赖旧环境的地方。

### C. 教学与编辑上下文

将本参考包的教学原件、历史任务书和新版要求一起放入 references。已有本地相关材料也并入，保留原件，不重复覆盖、不擅自改写学生稿。

重要材料包括：即兴表达教材、暑假课堂记录、回忆整理的真题、学生多次修改形成的村咖示范、历史样刊与反馈、插画需求、AI陪练指令。

把这些资料的性质标清楚：
- 教师明确要求；
- 课堂讨论与阶段性修改；
- 学生原稿；
- 助手试改（尚未获教师认可）；
- 待核实的报道或原文归属；
- 历史任务书（有部分已被最新要求替代）。

课堂原件包含学生信息，只作用户私密教学资料，公开示例另行匿名处理。本次不要把原件提交到公开仓库。历史材料中对来源、时长、规则的记载不等于已经核验的外部事实。

不要要求用户重新总结全部聊天。能从项目、现有任务文件和本参考包恢复的内容，由你整理。确实没有的文件，在缺失清单写明名称和影响；不伪造“已移交”。ZCode隐藏系统提示、其他项目对话和不可导出的内部记忆不在交接范围。

### D. 本机配置与启动经验

项目必需的配置，在用户同机私密交接范围内单独保存。普通文档只写配置项名称、用途、相对路径和是否已提供，不回显密钥、Cookie、Token等值。

无需配置即可完成的内容构建，优先验证。必须登录的服务或微信授权明确列出，不能承诺复制后所有会话永不过期；不复制整个浏览器档案或系统密码库。

记录现有端口、代理/直连例外、启动顺序、健康检查、自动任务、是否涉及付费调用、停止办法。登录或权限阻塞哪项，就标记哪项，不让可独立制作周刊的部分一起停住。

## 6. 把交接说明写成下一位 Agent 真能使用的入口

`README_先读我.md` 请控制简洁，至少说明：
- 项目是什么；用户这次为什么换 Agent；
- 先读 CURRENT_REQUIREMENTS，再看原教学材料和当前样刊；
- 最新样刊的真实位置和“未获教师内容定稿”的状态；
- 哪个目录是可编辑代码、哪个是私密参考、哪个保存数据；
- 已验证的内容构建命令和非破坏性检查入口；
- 哪些服务默认不会启动；
- 本轮有无缺失项；
- 给 Antigravity 的首次接手指令。

`HANDOVER.md` 必须根据实际代码和现场环境填写，不用一大篇新规划代替。尤其说明：
- 输入材料 → 内容源文件 → Markdown/HTML → PDF/分册，各环节对应哪个文件；
- 哪些是构建生成文件，不应只改导出后就丢失修改；
- 当前六篇评论与八条复述、六段原文的对应关系；
- 当前观点页只给两个观点等已知问题，不是默认保留的产品规格；
- 旧站与副本的运行关系、数据路径和定时任务隔离办法。

可以为 Antigravity 准备一份短项目规则，仅保留：任务目标、最新要求入口、观点发散与两段成稿的区别、原目录保护、私密资料处理。官方当前文档支持 `.agents/rules` 的工作区规则；具体版本与激活方式由接手端核对。不要修改全局 `~/.gemini/GEMINI.md`，不要创建几十条规则或把教材全部塞进常驻提示。

即使准备了规则文件，首次接手仍明确要求阅读入口文档，不以“会自动加载”代替实际阅读。

## 7. 验证不是只看文件拷完了

在新目录内完成并记录以下检查。测试结果区分通过、失败、未测试与需授权，不统一写“全部完成”。

**完整性**：主要目录存在；正文文件、索引、教学原件、最新内容源、HTML/PDF、图示与插画需求数量可核对；关键文件大小与哈希或等价校验已记录；没有指回旧库的可写路径。

**可编辑性**：在副本的临时输出位置，从真实内容源重新生成当前刊例的 Markdown/HTML/PDF，核对关键正文和分页没有意外缺失。不要覆盖归档成品后才发现版本变了。记录实际生成命令。

**资料可读性**：至少读取一条完整新闻正文、一篇完整评论原文，并能从样刊追到来源。只有摘要时要如实标明，不声称拥有全文。

**系统接手能力**：运行适合当前环境的既有测试；能做时验证站点与资料库的只读访问。测试用副本数据、独立端口，禁用副本的自动采集、AI分析、定时推送和其他有写入或付费副作用的任务。

先检查项目是否已经支持只读/离线/禁调度开关；没有时，可以只在副本做最小必要的开关适配，并注明改动。不能仅设置一个代码根本没读取的环境变量就说已禁用。

**外部服务**：RSSHub、we-mp-rss、浏览器、API等能验证多少写多少。依赖凭据或网络的检查允许列为未测，不用为了交接重新全网采集。旧站当前正常运行的功能不要被测试影响。

**Git边界**：确认本次未自动推送；新副本的重要文件不依赖旧worktree；未把私密配置和课堂原件纳入待提交内容。

内容重建和资料阅读一旦能通过，就具备先做周刊的基础；个别外部服务未迁好，应明确跟进，但不要把用户拖回“所有采集通道全部完善才能开始写作”。

## 8. Antigravity 接手后的首要任务

先接管和复现，再继续内容改进。不要刚打开工程就升级所有依赖、重构数据库、接入更多媒体或自动重做整本刊例。

新 Agent 先说明它已经理解的三个区别：
1. 事实复述不是压缩评论；
2. 观点页尽可能充分发散，范本才收束成两个主体段；
3. 独立原文学习，不是再把本期同样几篇评论切碎。

完成环境接手后，优先拿一则现有暖文制作一份新的完整三页评论校准稿：具体问题、多个有依据且互不重复的观点、细致推演、选定一条主线后的范本与拆解。不要只复制已经提供过的“求赞—给赞”成稿来证明学会了。

先展示新写作能力，再扩展到其他评论；仍然是在优化这份刊例，不是另建课程。新稿另存，原版保留。具体题目可由新 Agent 根据资料完整程度选择，不需要用户逐个审批工程步骤。

## 9. ZCode 完成后怎样回复用户

只需给出：
- 桌面交接目录的真实完整路径；
- Antigravity 应添加的文件夹路径；
- 确认原项目未删除、未覆盖、未被新任务写入；
- 代码、数据、教学资料是否齐全，以及有实际影响的缺失项；
- 已验证的生成命令与文件位置；
- 一段可直接粘贴给 Antigravity 的接手指令。

不要只回复“文件均已打包”；不要让用户手动逐个找数据库、原文、上游补丁或重新整理教法。完成了什么、没完成什么，以实际文件和验证结果为准。
